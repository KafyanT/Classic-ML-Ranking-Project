# Ad Ranking

Ранжирование объявлений внутри запроса (`query_id`) по `item_contact`, метрика — NDCG@10. Весь код — в `Ad_Ranking_Colab.ipynb` (запускается в Colab), отчёт — `README.md`, сабмиты — `solution*.csv` (`query_id`, `item_id`). Данные (`*.parquet`) в git не хранятся.

## Review guidelines

Отвечай на русском. Комментируй только реальные проблемы, без замечаний о стиле.

Считай серьёзными (блокирующими) ошибками:

- **Утечку таргета.** Позиция строки внутри запроса (train собран окнами вокруг контакта) не должна попадать в признаки. Target encoding, оценки cross-encoder и любые признаки, зависящие от `item_contact`, для train считаются только out-of-fold.
- **Нарушение схемы валидации.** Фолды разбиваются по `query_id`: все строки запроса в одном фолде. Признаки псевдо-выдач (раздел 7) собираются только внутри одного фолда.
- **Расхождение train и test.** Признаки для train и test считаются одной функцией `prepare()`; новые признаки, добавленные только к одной стороне, — ошибка.
- **Ошибки метрики.** NDCG@10 — одна функция для всех моделей, среднее по запросам с хотя бы одним контактом, ничьи разбиваются случайно. Сравнивать модели нужно на одних и тех же фолдах.
- **Неверный формат сабмита.** Колонки `query_id`, `item_id`; все пары из test ровно по одному разу; внутри запроса — по убыванию предсказанной релевантности.
- **Невоспроизводимость.** Случайные операции (фолды, перемешивание, LightGBM, обучение нейросетей) должны использовать фиксированный seed.
- **Нехватку памяти в Colab.** Загрузка `item_description` целиком или другие операции, которые заметно увеличивают пиковое потребление памяти на 7.8M строк.
- **Расхождение README и ноутбука.** Цифры NDCG и описания методов в `README.md` должны совпадать с результатами в ноутбуке.
